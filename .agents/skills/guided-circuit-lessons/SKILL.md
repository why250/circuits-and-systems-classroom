# 引导实验教学网页

将课题转化为学习者可以预测、操作、观察、解释和迁移的实验。使用当前项目的组件和经过验证的模型；模型正确、能操作，以及实际学习有效是三件需要分别验证的事。

## 确定学习起点

- 读取适用项目指令及 [项目参考](references/classroom.md)，定位现有同题页面、模型与检查命令。
- 从用户的目标和已确认的基础确定入口。缺少会影响课程的信息时，优先问学习基础或希望解决的问题；同时继续检查现有素材。不要重新询问已回答的问题。
- 该项目当前偏好：中文讲解，保留常见英文术语；采用引导实验。这属于项目默认，用户的新要求优先。
- 给每个实验定义可观察的学习成果，例如“能通过改变输入频率区分增益和时间失配”。从最小机制建立直觉，再增加通道、误差或约束；按课题决定实验数量。

## 设计实验而不是堆积控件

对每个学习目标组织以下循环，可根据课题适当调整：

1. **预测**：提出一个可由实验区分的具体问题。用合理误解作为选项，并提供“还不确定，先做实验”；预测不是阻止学习的门槛。
2. **实验**：给出可复现的基线、操作和比较对象。一次突出一个机制，固定无关参数；明确固定的是哪个量。每个可见控件应能帮助回答当前问题。
3. **观察**：显示实际输入、关键单位和读数。让相关图表同步，给出关闭当前误差或恢复本步参数的对照。解析预测与模拟测量应标明来源。
4. **解释**：学习者主动展开解释。把现象连接到机制，再给出简短公式、符号与近似条件。用户要直接阅读推导时，不强制先答题。
5. **迁移检查**：换一个条件验证同一机制，提供理由和针对误解的反馈。检查结果只表示本题反馈，不声称证明用户已掌握整门课。

设计相邻实验的差异时，注明参数改变应影响**位置、幅度、噪声底或指标**中的哪一项。频率、幅度、RMS、峰值、功率、单边谱等约定会改变结果时，要明确说明。

## 实现与验证

- 先复用同题模型和图表。教学内容、阶段状态和模拟计算分离；已有成熟功能需要保留时，增加学习模式或入口。
- 预测阶段使用清楚标记的基线，操作后同步更新图表；解释的展开与测验答案独立于参数变化。切换模式应尽量保留实验状态；阶段重置行为需要明确。
- 标明模型的输入、单位、假设、有效范围及未实现的机制。实际输入被相干频点、量化或边界处理改变时显示实际值。随机实验使用可复现种子，避免把一次随机波形当作确定性规律。
- 验证会影响教学结论的数值：优先独立解析关系、量纲、极限情况、独立时域/频域计算或 Python 参考。不要用页面自身的预测函数作为其正确性的唯一证据；无需为纯排版或文字写镜像测试。
- 使用项目规定的类型检查、测试和构建。浏览器实际走通预测、操作、对照、解释、错误答案反馈、阶段/模式切换；检查窄屏读图和键盘可操作性。工具限制或未验证部分如实报告。
- 延续现有网站外壳、主题、导航和访客统计约定。新增路由是否进入公开目录，应依据本项目的发布标准和本次用户要求；部署、提交或发布按已有授权执行。
- 本项目的托管目标是用户自己的 Cloudflare Pages 免费静态网站。用户请求上线时，按 [项目参考](references/classroom.md) 中的独立部署方式发布到已有 `why250-circuits-classroom` 项目，验证线上课题链接后交付；不要套用上游作者的账号、自定义域名或统计 Worker。

## 交付与迭代

交付可直接打开的页面；本地制作给出本地地址，已请求上线且验证成功时给出用户自己的 Cloudflare Pages 地址。指出学习入口、课程范围和验证结果。用实际学习反馈调整实验顺序、解释深度和交互；不要只凭通过测试就宣称教学有效。把新课题中验证过的共性更新到本 skill，课题特有的物理模型与推导保留在对应课题模块。

示例：

> 使用 $guided-circuit-lessons 帮我学习 PLL 环路带宽与相位噪声。我了解反馈和频谱，请先用单变量实验建立直觉，再解释公式，并在当前项目中生成教学网页。
